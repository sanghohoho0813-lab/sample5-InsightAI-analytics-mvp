# InsightAI — AI 데이터 분석·예측 반응형 SaaS MVP

> **미래에이아이랩(MIRAE AI LAB) 제작 레퍼런스**

**데이터를 넣으면, 무엇이 변했고 왜 변했고 지금 무엇을 해야 하는지 알려주는** 분석 SaaS입니다.
대상은 분석가가 없는 중소기업의 대표·운영·마케팅 담당자입니다.
판단 기준은 "데이터를 보여주는가?"가 아니라 **"대표나 실무자가 다음 행동을 정할 수 있는가?"**입니다.

## 핵심 흐름 (Golden Path)

1. **데이터 올리기 → 진단** — CSV·XLSX를 올리면 바로 분석하지 않고 먼저 보여줍니다.
   `열 인식`(파일의 열 → 인식한 항목 / 사용하지 않는 열) → `분석할 수 있는 것 / 없는 것`(그리고 무엇이 더 필요한지) →
   `기간`(빠진 날 수, 처음 열 비교 범위) → `데이터 품질`(제목 줄 건너뜀, 없는 날짜, 빈 매출, 완전히 같은 행, 빈 열, 짧은 기간) → `이대로 분석 시작`.
2. **대시보드 = 경영 브리핑** — 숫자 카드가 아니라 한 문장으로 시작합니다: `매출이 이전 30일보다 20.2% 늘었습니다.`
   그 아래 ① **가장 큰 변화**(증감분을 가장 많이 만든 채널·상품) ② **가능성 높은 원인**(그 변화를 방문자 × 전환율 × 객단가로 나눈 결과) ③ **지금 확인할 위험** ④ **추천 다음 행동**(각각 근거 수치 포함)이 이어지고, 결론마다 `근거 n개 보기`로 계산값을 펼쳐 확인합니다.
   지표는 카드 줄 대신 추이 차트 머리의 탭으로 들어가 있고, 그 아래 `평소와 달랐던 날`, `채널별 매출 변화`(증감액 막대), `그 밖의 발견`, `다음 7일 예측`이 이어집니다.
3. **이상치 → 조사 흐름** — `평소와 달랐던 날`의 한 행을 누르면 조사 화면(`/anomalies?id=…`)으로 갑니다.
   ① 무슨 변화인가(그날 값 vs 평소, 같은 날 함께 움직인 지표, 차트) → ② 언제 시작됐고 지금은?(시작 전 → 그날 → 회복일/진행 중) →
   ③ 어디서 생겼나(채널·상품별 몫) → ④ 확인할 수 있는 근거(지표별 그날·평소·같은 요일 평소) → ⑤ 지금 할 일(지표 조합으로 본 원인 유형과 확인 순서).
4. **드릴다운** — 브리핑·인사이트·질의 답변의 링크는 분석 화면으로 범위를 좁혀 이동하고, 돌아가면(링크·브라우저 뒤로) 원래 범위로 복원됩니다.
5. **보고서 = 업무 기록** — 그 시점의 결론을 `1. 핵심 요약 · 2. 분석 범위 · 3. 주요 발견 · 4. 위험 요소 · 5. 권장 행동 · 6. 생성 시점` 순서로 남깁니다. 저장 전 "이 결론이 기록됩니다" 미리보기, 제목 수정, `이 범위로 대시보드 열기`, PDF, 삭제 되돌리기.
6. **데이터 질의** — 일반 대화가 아니라 "지금 열린 데이터"에 묻는 도구입니다. 데이터에 맞춘 질문(`웹사이트 매출은 왜 늘었어?`, `10월 3일 웹사이트에 무슨 일이 있었어?`)을 추천하고, 답마다 **근거(화면과 같은 계산)**와 **이어서 볼 화면**을 붙입니다.

예외 상태: 브랜드 404 페이지, 화면 오류 시 `다시 시도`/`데모 데이터 비우고 시작` 화면, 손상된 저장 데이터는 읽을 때 걸러냅니다.

### 저장되는 상태 (localStorage, 키 접두어 `insightai.`)

| 키 | 내용 |
|---|---|
| `activeDataset` | 지금 분석 중인 데이터셋 id |
| `history` | 분석 기록 — 분석 시점의 실제 핵심 발견·매출 변화율·주의 이상치 수 |
| `uploads` | 업로드 원본(최근 3개, 용량 초과 시 오래된 것부터 정리 → 복원 불가 기록은 `원본 없음`으로 표시) |
| `reports` | 저장한 보고서 스냅샷 |
| `readNotifications` | 확인 처리한 이상치 id (사이드바·하단 탭 미확인 배지) |
| `settings` | 기본 분석 기간(7/30/90일) |

설정 → **데모 초기화**는 위 키를 모두 지우고 샘플 데이터로 다시 시작합니다.

## 내비게이션

- 데스크톱 사이드바: 핵심 6개(대시보드·이상 감지·인사이트·분석·예측·보고서) + 작업 공간 3개(데이터·데이터 질의·설정). 아이콘은 단색, 활성 항목만 브랜드 블루. 배지는 **미확인 이상치 수** 하나만.
- 상단 바: **데이터 전환 메뉴**(샘플 3종 · 올린 파일 · 파일 올리기) · `데모` 표기 · 오늘 날짜·요일·시각(분 단위). 페이지 제목과 대표 행동은 본문 `PageHeader`에 한 번만.
- 범위(기간·채널·상품)는 데이터를 보는 화면의 본문 상단에만 둡니다. 데스크톱은 한 줄 컨트롤, 모바일은 `최근 30일 · 전체 채널` 한 줄 요약을 누르면 **바텀시트**에서 한 번에 고르고 적용합니다. 값이 하나뿐인 차원(예: 채널 컬럼이 없는 파일)은 숨깁니다.
- 페이지 설명줄은 비교 기준을 한 줄로 보여줍니다: `최근 30일 · 이전 30일과 비교`. 대시보드는 대신 데이터 이름과 마지막 데이터 날짜(신선도)를 보여주고, 비교 기준은 브리핑 첫 줄에 둡니다.
- 모바일 하단 탭 5개: 홈 · 이상 감지 · 인사이트 · 보고서 · 더보기.

원칙
- 메뉴·지표마다 다른 색을 칠하지 않습니다. 색은 **브랜드(선택·행동)**와 **상태(좋음·주의·위험)**에만 씁니다. 상태는 항상 텍스트 라벨(위험·주의·참고)과 함께 표시합니다.
- 패널 안에 패널을 넣지 않습니다(카드 깊이 1). 목록은 구분선으로 나눕니다.
- 버튼 위계는 `lib/ui.ts`의 `btn.primary / secondary / quiet / danger` 네 가지. **primary는 화면당 하나.**
- 차트 색은 `lib/palette.ts` — 단일 지표는 브랜드 블루, 이전 기간은 옅은 블루 점선, 예측은 틸, 범주형은 블루 명도 단계 + 뉴트럴.
- 장식용 그라데이션·글로우·카운트업·"AI" 반짝이 아이콘을 쓰지 않습니다.

## 정직한 데모 표기 · 계산 규칙

- 상단 바 `데모` 배지, 분석 오버레이·인사이트·설정에 **규칙 기반 분석 엔진**임을 표시합니다.
- 이상치 감지 기준을 화면에 공개합니다: 평소 수준(직전 7일 중앙값)과 최근 4주 같은 요일 수준 **모두**에서 20% 이상(전환율·객단가 15%) 벗어난 날.
- 원인은 항상 **추정**으로 표기합니다(`가능성 높은 원인(추정)`, `데이터 패턴으로 본 추정`). 계산 방식(`매출 = 방문자 × 전환율 × 객단가로 나눈 계산`)을 근거 옆에 적습니다.
- 예측은 "최근 추세 기반 추정치"로 표기합니다. 실행 제안에는 **지어낸 효과 수치(예: 매출 +4~7%)를 쓰지 않고**, 제안을 만든 계산값을 `근거`로 답니다.
- 고객 유형별 금액은 "고객 수 비율로 나눈 추정치"로 표기하고, 원본에 없는 고객 유형별 전환율은 계산하지 않습니다.
- 업로드 파일은 서버로 전송되지 않고 브라우저에서만 처리됩니다.
- **이전 기간 비교**는 같은 길이의 직전 구간이 있을 때만 합니다. 비교할 수 없으면 증감 대신 `비교 없음`, 브리핑은 기간 안의 흐름(전반 vs 후반)으로 대신합니다. 업로드 파일은 데이터 길이에 맞는 기본 기간(예: 40일치 → 최근 7일 vs 이전 7일)으로 엽니다.
- **파일에 없는 컬럼**(주문 수·방문자·고객 수·광고비·채널·상품)은 내부 계산용으로만 추정하고, 그 추정치로 만든 지표·인사이트·예측·표 열·질의 답변은 내지 않습니다. 업로드 진단에서 무엇이 빠지는지 미리 알려줍니다.
- **최소 데이터**: 급변 감지 8일, 같은 요일 기준 15일, 예측 14일, 상품 흐름(최근 7일 vs 그 전 3주) 28일 이상. 부족하면 이유를 표시합니다.
- **이상치 정리**: 주말처럼 반복되는 요일 패턴과 프로모션이 끝나 평소로 돌아온 날은 알리지 않습니다. 며칠 이어진 변화는 시작일·지속 일수를 가진 한 건으로, 여러 채널이 함께 움직이면 `전체` 한 건으로 묶습니다. 방문자가 급감해 전환율이 높게 계산된 날은 '전환율 급증'으로 따로 알리지 않습니다. 상승은 `참고` 등급입니다.

## 데모 데이터 스토리 (이커머스)

데모 데이터는 **접속한 날을 마지막 날로 하는 최근 90일**로 생성됩니다. 이벤트도 마지막 날 기준 상대 위치로 정의되어,
언제 열어도 "최근에 벌어진 일"로 읽힙니다.

- 21~15일 전: 프로모션 — `전체 매출·주문 수 급증`(참고) 한 건으로 묶여 감지
- 11일 전: 웹사이트 방문자 급감 — `위험`, 조사 화면에서 "방문자(−71%)가 주문(−44%)보다 훨씬 크게 줄었다 → 광고 중단·접속 장애·집계 누락 확인"

- 6일 전~오늘: 웹사이트 전환율·객단가 개선(참고)

## 개발자 가이드

### 구조와 데이터 흐름

```
demo-data / csv(업로드 + 진단)    ← 원본 행(DataRow) — 브라우저 밖으로 나가지 않음
        │
        ▼
analytics-engine  기간 해석 · 집계 · 이전 기간 비교 가능 여부
drivers           요인 분해(방문자×전환율×객단가) · 기여도 · 상품 흐름 · 광고 효율 · 기간 안 흐름
anomaly-engine    평소 수준(7일 중앙값·같은 요일) 대비 탐지 → 묶기(일수·전체/채널) · 비율 착시 제거
investigate       이상치 하나의 조사: 무엇 → 언제 → 어디서 → 근거 → 원인 유형·할 일
insight-generator 계산된 발견(근거·계산 방식 포함) · 발견에서 나온 실행 제안
forecast-engine   추세 → 7일 추정
        │
        ▼
briefing.summarize  헤드라인 → 가장 큰 변화 → 가능성 높은 원인 → 지금 확인할 위험 → 다음 행동
                    ── 대시보드 · 보고서 스냅샷 · 분석 기록 · 데이터 질의 · LLM 요약이 같은 함수를 쓴다
qa                  질문 의도 → 같은 계산으로 답 + 근거 + 이어 볼 화면 · 데이터별 추천 질문
dataset-meta / capabilities   추정 필드에 기대는 지표 걸러내기 · 이 데이터로 할 수 있는 분석
        │
        ▼
store (React Context)  ←→  persist (localStorage: 검증된 읽기 · 용량 초과 대응)
        │
        ▼
화면 (app/(app)/*)      ai/client → /api/ai (선택) → Claude API
```

- **엔진은 순수 함수**입니다. React·브라우저에 의존하지 않아 단위 테스트로 규칙을 고정합니다.
- **화면의 모든 숫자는 한 계산 경로**에서 나옵니다. 대시보드 브리핑, 저장 보고서, 분석 기록, 데이터 질의, LLM에 보내는 요약이 `summarize`를 공유해 서로 어긋나지 않습니다.
- **상태 경계**: 범위(기간·채널·상품)는 전역 상태이고, 드릴다운은 출발 화면과 이전 범위를 `drill`로 기억해 돌아갈 때(링크·브라우저 뒤로) 복원합니다(`components/DrillWatcher.tsx`).

### 데이터 질의 (LLM, 선택)

- 브라우저는 `/api/ai`만 호출하고 키는 서버(`ANTHROPIC_API_KEY`)에만 둡니다. 모델은 `AI_MODEL`(기본 `claude-opus-5-5`).
- 원본 행이 아니라 **화면과 같은 계산으로 만든 요약**(`lib/ai/context.ts`, 12KB 이하 — 브리핑 결론 포함)만 보내고, 시스템 프롬프트로 "요약 안의 숫자만 근거로, 화면의 결론과 같은 방향으로, 일반론 없이, 없는 값은 모른다고" 답하게 합니다. 질문은 `<question>` 태그로 분리해 지시 주입을 막습니다.
- 요청·응답 형식은 `lib/ai/contract.ts` 한곳에서 정의하고 서버·클라이언트가 같은 검증을 씁니다(질문 300자, 요약 크기 제한).
- 키 없음·거절(`refusal`)·호출 실패·20초 초과 시 규칙 기반 엔진으로 넘어갑니다. LLM이 답해도 **근거와 이어 볼 화면은 항상 규칙 기반 계산**에서 만들고, 답마다 출처(`AI가 쓴 문장` / `규칙 기반 계산`)를 표시합니다.
- 인스턴스 단위 호출 제한(IP당 분당 20회). 여러 인스턴스에서 공유하려면 외부 저장소로 옮깁니다.

### CI

`.github/workflows/ci.yml` — 푸시·PR마다 typecheck → lint → 단위 테스트 → 빌드, 이어서 E2E(데스크톱·모바일·접근성). 실패 시 Playwright trace를 아티팩트로 남깁니다.

### 설계상 선택

- **규칙 기반이 기본**: 같은 데이터면 언제나 같은 결과가 나오고 설명 가능해야 하므로, 판단(탐지·요인·제안)은 규칙으로 하고 LLM은 "질문에 자연어로 답하기"에만 씁니다.
- **결론마다 근거**: 브리핑·인사이트·제안·질의 답변은 모두 "결론 → 계산값(근거) → 계산 방식"을 갖습니다. 근거를 댈 수 없는 문장(예: "마케팅을 강화하세요")은 만들지 않고, 단위 테스트로 막습니다.
- **평소 수준은 중앙값과 같은 요일로**: 평균·전일 대비는 프로모션·주말에 흔들려 거짓 경보가 많습니다. 두 기준 모두에서 벗어나야 알립니다.
- **원인 분해는 로그 분해**: 매출 변화(ln R₁/R₀)를 방문자·전환율·객단가의 로그 변화로 나누면 몫의 합이 정확히 100%가 됩니다.
- **추정치는 숨긴다**: 업로드 파일에 없는 컬럼은 계산 편의상 추정으로 채우지만, 그 값에 기대는 지표·인사이트·표 열·질의 답변은 내보내지 않습니다.
- **비교는 같은 길이일 때만**: 이전 구간이 모자라면 증감 대신 "비교 없음" — 가짜 +100%를 만들지 않습니다.
- **보안 헤더**: `nosniff`, `Referrer-Policy`, `Permissions-Policy`, 틀(iframe) 허용은 자기 자신과 miraeailab.com으로 제한.
